UOM editor:
the editor when first displayed should not show every uom in the database, but require the user to execute a filter
the type (e.g. length, mass) must be an enumerated type rather than just a string and referenced in the uom editor when creating a uom
the end user must be able to create their own type (e.g. rope) and custom uom (e.g. coil) that references it, 1 coil = 100 meters.  
display the uom next to multiplier value, e.g. 1 ft = .3048 meter.  
when creating a custom uom that references another uom, the user must choose the already created uom (e.g. meter)
the multipler cannot be edited for physical units of measure that have known values, e.g. feet and meters
 
Material Editor:
the editor when first displayed should not show every material in the database, but require the user to execute a filter
material editor must allow the user to choose a pre-defined unit of measure
