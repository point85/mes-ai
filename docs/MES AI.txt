MES AI

Objective
I want to build a free and open source Manufacturing Execution System (MES) that will be designed, coded and tested solely by an AI (you).  
The code should never need to be looked at or maintained by a human, but rather by an AI coding agent.  
Therefore the implementation should be optimized for ease of maintenance and enhancements by an AI, not by a human.

The duration of the project will be many weeks and will cross sessions, therefore there must be a procedure in place to resume work where a previous session left off without needing to understand the implementation from scratch.  
Also, I need to be able to refer to a module of functionality by an identifier for enhancements rather than describe what it does to save time and token expense.

The project deliverable will be an MES framework with plug-in functionality (much like a coding IDE has plugins).  
An end user will download the framework from GitHub and proceed to customize the functionality based on their unique requirements.  
Using their preferred IDE (e.g. Claude Code, Visual Studio Code, etc.), they will describe to the AI agent what customizations they require, and the AI will proceed to implement them.

The first task is to create and document a project plan describing step-by-step what implementation tasks will be accomplished.  
I will decide if a task has been completed and we will move on to the next task.

Features
A MES is software used in a factory to produce goods effectively.  
It interfaces to an Enterprise Resource Planning (ERP) at inbound touchpoints (e.g. production orders, and manufactured materials) as well as at outbound touchpoints (e.g. work in process reporting and consumption of raw materials).  
An MES also interfaces to production equipment controllers (e.g. Programmable Logic Controllers or PLCs and microcontrollers) as well as test equipment for test results.

An MES tracks the progress of work-in-process (WIP) represented by units or lots of material through the physical model of production lines, work centers and equipment.  
A dispatching algorithm upon the occurance of a production event decides what work center or equipment to move the work (unit or lot) to.  
The dispatching could be manual in which case an operator enters a disposition mapped to a destination.  
Or the dispatching could be automated based on the downstream equipment�s capability and capacity to receive additional work.

The end user will use an IDE such as Claude Code or VS Code to implement new features.  We will use VS Code to develop the MES framework.  
A Git repository will be used to store all artifacts from which the end user will download the framework and proceed to make their customizations.

Implementation
The major phases to accomplish the goals of this project are:
!1)	Survey existing commercial MES�s and their capabilities and create a list of required functionality, then document the conclusions.
(2)	Propose an implementation architecture.  The system should be client/server with a REST HTTP/HTTPS interface between clients and a server.  
The clients can be written in the programming language of the end user�s choice.  
A runtime client that manipulates WIP can have a GUI for use by a human or can be headless if interfacing to automated equipment for example.  
A design time client will allow the end user to view what funtionality has been implemented and how the pieces �fit together�.  
The server will provide MES capabilities and store data in a Relational Database Management System (RDBMS) for tracking and reporting purposes.
(3)	Divide up the implementation into a series of manageable implementation tasks starting with the server. 
Automated testing needs to be implemented to verify that a task has been complemented.  
For the physical environment of an ERP, controllers or test equipment, it is not feasible to test against �real� interfaces or devices.  In this case, mocking up an interface will be required.


How to resume a future session: Say "Resume MES AI project" — I'll read PROJECT_STATE.json and SESSION_LOG.md to pick up exactly where we left off.

How It Works
Session start: You paste a single prompt like "Resume MES AI project" — the AI reads PROJECT_STATE.json and SESSION_LOG.md, instantly knows the current state, and picks up where it left off.
During session: As work progresses, both files are updated incrementally.
Session end: A final update captures exactly where we stopped and what's next.
Module IDs: Every functional module gets a short identifier (e.g., WIP-TRACK, DISPATCH-ENGINE, ERP-ADAPTER) registered in PROJECT_STATE.json. You reference these IDs instead of describing functionality.

The simulator's in-memory data in sap_data.py uses the same field names (AUFNR, MATNR, WERKS, etc.) as real SAP OData responses, so the shared transform layer processes them identically. This means the simulator exercises the full field-mapping pipeline without needing a live ERP.

In this MES:

Material — a raw material, component, or consumable that is consumed during manufacturing (e.g. resin pellets, PCB blanks, labels, solder paste). Materials have a material_type (raw, component, consumable, finished), a UOM, and are tracked via lots with inventory balances.

Product — the finished good being manufactured (e.g. "Shampoo Bottle 500ml", "PCB Assembly X200"). A product owns a BOM (bill of materials listing which materials are consumed and in what quantities) and one or more process routes (the sequence of steps to produce it). Production orders reference a product.

In short: products are what you make; materials are what you use to make them. The BOM links the two — it says "to build Product X, consume these Materials in these quantities at these route steps."
